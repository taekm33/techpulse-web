"AI 코딩 도구, 진짜 써보면 어때요?" 이 질문에 6개월치 실무 데이터로 답할 수 있게 됐다. 프론트엔드(React/Next.js)와 백엔드(FastAPI/Node.js) 혼합 프로젝트를 Cursor와 함께 진행하며 생산성, 한계, 비용 효율을 직접 체감했다. 결론부터 말하자면 **"쓸 만하다"와 "만능은 아니다"가 동시에 참**이다.

---

## Cursor란 무엇인가

**Cursor**는 샌프란시스코 스타트업 Anysphere가 개발한 AI 네이티브 코드 에디터다. VS Code를 포크(fork)해 만든 탓에 기존 VS Code 사용자라면 설정·익스텐션·단축키 거의 그대로 가져올 수 있다. 단, 단순히 AI 플러그인을 얹은 수준이 아니라 에디터 자체에 AI 기능이 깊숙이 통합돼 있다는 점이 다르다.

핵심 차별점은 **코드베이스 전체를 컨텍스트로 활용**한다는 것이다. 단일 파일이 아니라 프로젝트 구조, 타입 정의, 관련 파일을 AI가 참조하며 응답한다.

---

## 주요 기능 상세

### Tab 자동완성

Cursor의 Tab 자동완성은 GitHub Copilot과 가장 직접 비교되는 기능이다. 단어 단위가 아니라 **여러 줄 단위**로 미래 코드를 예측해 제안한다.

체감 특징:
- 현재 파일의 패턴을 학습해 일관된 코딩 스타일로 제안
- 커서 위치 앞뒤 맥락을 함께 보고 "중간 완성"도 지원
- `Tab`으로 수락, `Esc`로 거절, 부분 수락은 `Ctrl+→`

6개월 동안 가장 많이 쓴 기능이다. 반복적인 CRUD 코드나 테스트 코드 작성에서 체감 속도가 눈에 띄게 빨라졌다.

### Chat (인라인 채팅 & 사이드바 채팅)

`Ctrl+L`로 사이드바 채팅, `Ctrl+K`로 인라인 편집 모드를 연다.

- **사이드바 채팅**: "이 함수에서 발생할 수 있는 엣지 케이스를 알려줘" 같은 질의응답
- **인라인 편집(Ctrl+K)**: 선택한 코드 블록을 직접 수정 지시. diff 형태로 변경 사항을 보여주고 수락/거절 선택 가능

> 인라인 편집이 특히 강력하다. 리팩토링 지시를 내리면 현재 코드 바로 아래에 변경 diff가 뜨기 때문에 문맥 전환 없이 바로 검토·수락할 수 있다.

### Composer (에이전트 모드)

`Ctrl+I`로 여는 Composer는 Cursor의 핵심이다. 단일 파일을 넘어 **여러 파일을 동시에 생성·수정**하는 에이전트 기능이다.

"사용자 인증 기능 추가해줘. JWT 기반으로, 로그인·로그아웃·토큰 갱신 API 포함. FastAPI 프로젝트야."라고 입력하면:
1. 기존 프로젝트 구조 파악
2. `auth/router.py`, `auth/models.py`, `auth/utils.py` 신규 생성
3. `main.py`에 라우터 등록 코드 삽입
4. `requirements.txt`에 의존성 추가

까지 한 번에 처리한다. 물론 검토는 필수지만, 초안 생성 속도가 압도적이다.

### @코드베이스 검색

채팅에서 `@codebase`를 입력하면 프로젝트 전체를 벡터 검색해 관련 파일·함수를 컨텍스트로 끌어온다.

- `@파일명`: 특정 파일 참조
- `@폴더명`: 폴더 전체 참조
- `@Docs`: Cursor에 등록한 외부 문서(Next.js 공식 문서 등) 참조
- `@Web`: 실시간 웹 검색 결과 참조 (Pro 이상)

이 기능 덕분에 "우리 프로젝트에서 결제 관련 로직이 어디에 있어?" 같은 질문을 자연어로 던질 수 있다.

## 실제 사용 시나리오별 체험

### 새 기능 구현 ★★★★★

가장 만족스러운 영역이다. 요구사항을 충분히 설명하면 여러 파일에 걸친 기능 구현 초안을 빠르게 뽑아준다. 세부 조정은 필요하지만, 빈 파일에서 출발하는 것 대비 시간이 60~70% 절감되는 느낌이다.

### 버그 수정 ★★★★☆

에러 메시지와 관련 코드를 함께 붙여넣으면 원인 분석과 수정 코드를 잘 제시한다. 다만 복잡한 상태 관리 버그(React Context 깊은 곳에서 발생하는 상태 불일치 등)는 AI가 정확한 원인을 놓치는 경우가 있었다.

### 리팩토링 ★★★★☆

"이 서비스 레이어를 repository 패턴으로 분리해줘"처럼 구체적인 패턴을 명시하면 결과가 좋다. 모호한 "더 좋게 만들어줘" 스타일의 지시는 결과가 들쭉날쭉하다.

### 코드 이해 ★★★★★

처음 보는 레거시 코드베이스를 파악할 때 진가를 발휘한다. `@codebase`로 전체를 연결한 뒤 "이 프로젝트에서 주문 처리 플로우를 설명해줘"라고 물으면 관련 파일들을 엮어 명쾌하게 설명한다. 온보딩 시간이 크게 줄었다.

| 항목 | GitHub Copilot | Cursor | Windsurf |
|---|---|---|---|
| **기반 에디터** | VS Code 플러그인 | VS Code 포크 | VS Code 포크 |
| **Tab 자동완성** | ★★★★ | ★★★★★ | ★★★★ |
| **채팅 기능** | ★★★ | ★★★★★ | ★★★★ |
| **에이전트 (다중 파일)** | ★★★ (Workspace) | ★★★★★ (Composer) | ★★★★★ (Cascade) |
| **코드베이스 검색** | ★★★ | ★★★★★ | ★★★★ |
| **외부 문서 연동** | 제한적 | ★★★★★ | ★★★ |
| **VS Code 익스텐션 호환** | 완전 호환 | 대부분 호환 | 대부분 호환 |
| **응답 속도** | 빠름 | 보통~빠름 | 보통 |

> Copilot은 GitHub 생태계 통합(PR 리뷰, 이슈 연동)이 강점. Cursor는 에이전트 기능과 컨텍스트 깊이에서 앞선다. Windsurf는 Cascade 에이전트의 흐름이 자연스럽다는 평가가 많다.

## 단점과 한계

### 1. AI 환각(Hallucination)
존재하지 않는 함수나 API를 자신 있게 제안하는 경우가 있다. 특히 덜 알려진 라이브러리나 최신 버전 API에서 발생 빈도가 높다. **반드시 직접 실행·검증 과정이 필요하다.**

### 2. 컨텍스트 한계
프로젝트가 매우 크거나(수십만 줄 이상) 파일 수가 많으면 `@codebase` 검색 정확도가 떨어진다. 관련성 낮은 파일이 컨텍스트에 끼어드는 경우도 있다.

### 3. 긴 Composer 세션의 불안정성
Composer로 많은 파일을 동시에 수정하는 대규모 작업 중 컨텍스트가 흐트러지는 경우가 있다. 중간중간 새 Composer 세션으로 분할하는 것이 실무상 더 안정적이다.

### 4. 보안·개인정보 우려
Pro 플랜 기본 설정에서는 코드가 AI 모델 서버로 전송된다. 민감한 코드베이스(금융, 의료, 내부 알고리즘)를 다루는 팀은 **Privacy Mode** 설정 또는 엔터프라이즈 플랜을 검토해야 한다.

### 5. 가격 부담
개인 개발자에게 월 $20은 체감상 작지 않다. 무료 플랜은 GPT-4 수준 모델 사용 횟수가 엄격히 제한돼 실질적인 업무 활용은 어렵다.

## 가격 비교표

| 플랜 | 가격 | 주요 내용 |
|---|---|---|
| **Free** | 무료 | 기본 자동완성, 프리미엄 모델 50회/월, Composer 제한 |
| **Pro** | $20/월 | 프리미엄 모델 무제한*, Composer 무제한, @Web 검색 |
| **Business** | $40/월/유저 | 팀 관리, Privacy Mode, SSO, 사용량 대시보드 |

*무제한이지만 과도한 사용 시 속도 제한(rate limit) 적용

> 비교 기준: GitHub Copilot Pro는 $10/월이지만 에이전트 기능이 약하고, Windsurf Pro는 $15/월로 Cursor 대비 저렴하지만 @Docs 등 일부 기능이 빠진다. 비용 대비 효율은 팀의 사용 패턴에 따라 다르다.

## 어떤 개발자에게 추천하는가

### 강력 추천
- **풀스택 개발자**: 여러 파일에 걸친 기능 구현 시 Composer 에이전트가 빛난다
- **새 프로젝트 잦은 개발자**: 보일러플레이트 생성 속도가 압도적
- **레거시 코드베이스 투입 개발자**: 코드베이스 이해·탐색 기능이 온보딩을 단축

### 조건부 추천
- **팀 단위 도입**: Business 플랜의 Privacy Mode와 관리 기능 확인 필수
- **특정 언어 집중 개발자**: Python, JS/TS에서 성능이 가장 안정적. Rust, Go는 양호, 비주류 언어는 결과 편차 큼

### 비추천
- **보안 규정이 엄격한 환경**: 코드 외부 전송이 정책 위반이 될 수 있음
- **인터넷 단절 환경**: 로컬 모델 연동 설정 없이는 사실상 사용 불가
- **AI 코드를 무검증 사용하려는 경우**: AI 제안을 그대로 믿고 배포하면 반드시 사고 난다

## 총평

Cursor는 과장이 아니라 코딩 생산성을 실질적으로 높여주는 도구다. 특히 에이전트 방식으로 여러 파일을 한 번에 다루는 Composer는 경쟁 도구 중 가장 완성도가 높은 편이다. 하지만 AI 코딩 도구는 **속도 부스터**이지 **대체제**가 아니다. 생성된 코드를 이해하고 검증할 역량이 있는 개발자가 쓸 때 극대화된다.

6개월 후 내 결론: 계속 쓴다. 단, 코드리뷰는 여전히 사람이 한다.
